# Z 团队财务 Agent

范围：`19116819870@chatroom`（Z团队性价屋对接群）。托管账号沿用现有微信桥，模型沿用转发服务已配置的 DeepSeek。主人稳定联系人为 `ZML741213442`。

## 使用

1. 管理员进入 `/admin/finance-agent` 配置并核对微信账号、主人及成员绑定。昵称仅作参考；不要仅凭同名自动绑定。
2. 群内直接发送清晰原图，不必 @。未绑定发送者先请管理员绑定，再重新识别。网页也可上传。
3. Agent 提取逐笔交易与月度汇总。回复 `确认 单号 2026-10` 后入账。截图到账月份与结算月份分开；其他图片月份可在网页选择。
4. 默认报账人也是支出垫付人；代报由管理员在网页指定垫付人。疑似重复不会新增，可由管理员关联完全匹配的已有台账 ID。
5. 每位成员回复 `2026-10 已报齐`，再回复 `财务统计 2026-10`；管理员也可在核实报齐后从网页生成审核。
6. 统计只先私发给主人。主人私聊回复 `确认发布 审核单号` 或 `拒绝 审核单号`。其他发送者和群内回复不能代审；数据、规则、成员收款信息有变则审核失效，需重生成。

## 数据与异常

- 原图保存在 SQLite 私有 BLOB，访问需要管理员登录；保留提取结果、确认记录与台账关联。图片内文字属于证据，不能改变 Agent 规则。
- 金额以分入账。退款、模糊日期、混合收支、逐笔与汇总不符会停在人工核对，不猜金额和归属。
- 同消息、同图片及重复交易拦截。待核对凭证可取消，已入账凭证须在台账更正。
- 发送任务区分 queued / dispatched / accepted / failed / uncertain。API accepted 不代表人已阅读；未知结果不自动重发。
- 启用财务群后，该团队原有“已有数据就自动结算推送”入口停止，由报齐与主人审核流程接管。管理员旧手动结算入口仍可使用。

## 私有配置与部署

`data/finance-agent-private.json`（不提交）包含用途独立的 `bridge_token` 和固定 `recognize_url=https://zf.xingjiawu.cn/api/finance-agent/recognize`。DeepSeek 密钥仅在现有转发服务保存，不复制到财务库。桥接服务只接受这个专用凭据。

数据库只新增 finance_* 表；原台账不迁移。发布前备份 SQLite，并保留旧代码与 PM2 回退点。共享微信桥需单独验证现有登录与原业务健康。
